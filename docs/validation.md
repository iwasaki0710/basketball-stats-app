# 検証結果

この開発環境で実行し、以下が成功しました。

- `npm run typecheck`：TypeScript型チェック。
- `npm run format:check`：ソースとドキュメントの書式。
- `npm run build`：Next.jsの本番ビルド。
- `npm test`：**27件**。シュート・得点・出場時間・Plus/Minus・Q・延長のチームファウル継続・Undo・訂正・途中記録・得点ラン・入力検証・CSV数式対策・公開キーの検査・アカウント別保存キー・オフライン編集の3-way merge。PGliteでは初期SQL→既存データを残した002への更新、RLSによるチーム隔離、役割別権限、写真・相手イベントの正規化保存、revision競合とロールバックを検証。
- `npm run test:e2e`：ChromiumのPC・iPhone相当の画面幅で**28件**。画面遷移、選手と試合の登録、写真、成績推移、レーダー、対戦相手別分析、得点・Undo・訂正・交代、相手スタッツと時刻訂正、時計の開始・停止・画面移動・再読み込み・Q移行・終了、オフライン再読み込みと入力、JSON復元と不正ファイル拒否、別タブの上書き拒否、旧localStorageの移行、5MB超の記録のIndexedDB保存と再読み込み。公開デモの記録・リセット・チームデータからの分離と、デモ専用HTMLでのオフライン再読み込みも確認。
- オフライン再読み込みのケースは、ブラウザの通常のHTTPキャッシュを削除し、Service Workerのキャッシュからアプリを復元できることもPC・モバイルの両方で確認。
- `npm run test:auth`：隔離した一時ディレクトリでクラウド構成をビルドし、**擬似認証・デモ4シナリオ**を検証。未ログイン時の画面制限とメールリンク要求、認証済みユーザーの記録読み込みとログアウト、別アカウントへのキャッシュ非混在。設定済みSupabaseと期限切れの私用セッション・私用キャッシュが残る条件でも、公開デモがそれらを読み込まず、認証・クラウド通信を行わないことを確認。実Supabaseへは接続せず、テスト用のセッション・HTTP応答を使います。
- `npm run setup:check`：現在の環境にはSupabase設定がないため、想定どおり「未設定」として終了することを確認。実接続の成功を示す結果ではありません。

架空データの画面画像は `docs/screenshots/` にあります。

## 実サービス作成後に確認すること

実Supabaseプロジェクトのメール配信・SMTP、実際の認証セッションとクラウド同期、実機iOS/Safariは未検証です。ユーザーの画面から、既存版の本番ログイン画面と固定ドメインを確認しています。公開デモの本番利用は、最新コミットをVercelへデプロイした後に確認してください。[作成・公開の手順](launch-guide.md)に沿って設定後、チームの権限と別端末・オフライン再接続を確認してください。

モバイル自動テストはデスクトップChromium上のiPhone相当のエミュレーションです。実機Safariでの検証とは区別しています。
