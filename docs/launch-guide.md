# はじめての本番公開：Supabase と Vercel の接続

この手順で、ログインして複数端末から使えるURLを作れます。**クラウド開発環境の「公開」とは別の操作**です。Supabase・Vercelのアカウント作成とログインはご本人のブラウザで行ってください。パスワードや秘密キーをチャットに送る必要はありません。

## 1. Supabase のプロジェクトを作る

1. [Supabase Dashboard](https://supabase.com/dashboard) を開き、GitHubなどでログインします。
2. 初めての場合はOrganizationを作成します。まずは無料プランを選択できます。
3. 「New project」でプロジェクトを作成します。名前は `courtvision` などで構いません。
4. Database passwordは新しく生成し、パスワード管理ソフトへ保存します。アプリやGitHubには書き込みません。
5. Regionは利用場所に近いものを選びます。日本での利用ならTokyoが候補です。
6. プロジェクトの準備完了まで待ちます。

## 2. データベースと権限を作る

新規プロジェクトで、まだこのアプリのSQLを実行していない場合：

1. プロジェクトの「SQL Editor」で新しいクエリを開きます。
2. このリポジトリの [`supabase/schema.sql`](../supabase/schema.sql) を開き、**ファイル全体**をコピーします。
3. SQL Editorへ貼り付けて「Run」を実行します。
4. エラーがないことを確認します。チーム、権限、選手、試合、イベントのテーブルとRLSが作成されます。

**以前に `001_initial.sql` を実行したプロジェクトでは、schema.sqlを再実行しません。** その場合は [`002_complete_recording.sql`](../supabase/migrations/002_complete_recording.sql) だけを追加実行してください。既存データは保持されます。

RLSをオフにしたり、`service_role` でブラウザからアクセスする設定に変更しないでください。

## 3. 公開用の接続情報を確認する

Supabaseの「Connect」、またはプロジェクト設定の「Data API / API Keys」で、以下を確認します。画面の表記は更新されることがあります。

| 確認する情報                                                | アプリに設定する名前            |
| ----------------------------------------------------------- | ------------------------------- |
| Project URL（`https://...supabase.co`）                     | `NEXT_PUBLIC_SUPABASE_URL`      |
| Publishable key（`sb_publishable_...`）または従来のanon key | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |

**Secret key、`sb_secret_...`、service_role key は使いません。** アプリは誤って秘密キーを設定した場合、起動・ビルドを拒否します。公開キーもチャットへ貼り付けず、次のVercelのEnvironment Variablesへ直接登録してください。

## 4. GitHubのコードを確認する

[アプリのリポジトリ](https://github.com/iwasaki0710/basketball-stats-app) を開きます。`app/`、`components/`、`supabase/`、`package.json` がある版を使ってください。

Vercelにはこのリポジトリを読み取れるGitHubアカウントでログインします。リポジトリがPrivateの場合、VercelのGitHub連携で、このリポジトリへのアクセスを許可してください。

## 5. Vercelでアプリを公開する

1. [Vercelの新規プロジェクト](https://vercel.com/new) を開き、GitHubでログインします。
2. Gitリポジトリの一覧から `iwasaki0710/basketball-stats-app` を選び「Import」します。
3. Framework Presetは **Next.js**、Root Directoryはリポジトリのルートのままにします。
4. Node.js Versionは **24.x** を使用します。Install Commandは `npm ci`、Build Commandは `npm run build` です。
5. 「Environment Variables」に手順3の **2つの値** を設定します。まずProductionを対象にしてください。プレビューでもクラウドを使う場合はPreviewにも設定します。
6. 「Deploy」を実行し、完了後に表示されるアプリのHTTPS URLを控えます。

この時点ではログインメールを送る前に、次の手順を済ませてください。

## 6. Supabaseのログイン先URLを登録する

1. Supabaseの「Authentication → URL Configuration」を開きます。
2. 「Site URL」に、Vercelで発行されたアプリURL（例：`https://あなたのプロジェクト.vercel.app`）を設定します。
3. 「Redirect URLs」にも同じアプリURLを登録し、保存します。
4. 「Authentication → Sign In / Providers」でEmailを有効にします。
5. プレビューURLや独自ドメインを使う場合は、その利用するURLもRedirect URLsへ個別に登録してください。

### 部員へメールを送るためのSMTP設定

Supabase標準のメール送信には、宛先・回数などの制限があります。自分のテストに成功しても、部員全員へ送れることは保証されません。**チームで本運用する前に、AuthenticationのカスタムSMTPを設定してください。**

既存のメール送信サービスがあれば、そのSMTP情報を使います。新しく用意する例としては以下があります。

- **Googleのメールアカウントを使う場合**：2段階認証とアプリパスワードを利用できるアカウントで、Googleの公式手順に従ってSMTP用アプリパスワードを発行します。SupabaseのSMTP設定にはホスト `smtp.gmail.com`、ポート `465`、ユーザー名はメールアドレス、パスワードはそのアプリパスワード、Sender emailは同じ送信元アドレスを設定します。通常のログインパスワードは使いません。組織の設定でアプリパスワードを使えない場合は別のサービスを選びます。
- **Resendなどを使う場合**：サービスのアカウントを作成し、所有ドメインのDNSで送信元を検証します。サービスが表示するSMTPホスト・ポート・ユーザー・認証情報を、SupabaseのSMTP設定へ登録します。送信元は検証済みのアドレスを指定します。

SMTPのパスワードやAPIキーは**SupabaseのSMTP設定だけ**に入力します。GitHub・VercelのPUBLIC環境変数・チャットには貼り付けません。TLSの検証を無効にしないでください。

設定後、管理者本人と別の部員の両方へテストメールを送り、迷惑メールも確認します。送信上限と組織の運用ルールも確認してください。

メールを日本語にするには、AuthenticationのEmail TemplatesでMagic LinkとConfirm Signupの件名を「COURTVISION ログインリンク」にし、本文に [`supabase/templates/magic-link.html`](../supabase/templates/magic-link.html) を使えます。テンプレート内の `{{ .ConfirmationURL }}` は変更しません。

## 7. 初回ログインとチーム作成

1. VercelのアプリURLを開きます。メールアドレスを入力してログインリンクを送信します。
2. メールを、アプリを使うブラウザで開いてログインします。
3. 設定・データ管理で、チーム名とシーズンを設定します。
4. 「新規クラウドチーム」を押します。このアカウントが管理者になります。
5. 選手を5人以上登録し、試合を作成してプレーを入力します。
6. 設定の同期状態が「クラウド同期済み」になることを確認します。

ローカル版から実データを移す場合は、先にローカル版の設定からJSONをバックアップし、本番版へログインした後に復元してください。復元すると同期はいったん解除されます。既に保存済みのチームと取り違えないよう、移行後にクラウドチームを作成・接続してください。

## 8. 部員・スタッフを追加する

1. 追加する方にも、同じURLで一度メールログインしてもらいます。
2. 管理者の設定画面で、その方の登録済みメールを指定します。
3. 「管理者」「記録担当」「閲覧者」を選び、メンバーを追加します。
4. 追加された方は、設定で「チーム一覧を取得」→ 対象のチームを選択 → 「クラウドを読み込む」を実行します。

別アカウント・別端末で、許可したチームだけが見えることと、閲覧者が記録を変更できないことを確認してください。

## 9. 本番で使う前の確認

- 別端末で同じ記録を読み込める。
- 相手の詳細記録を有効にした試合で、相手の成功・失敗も入力できる。
- 誤入力のUndo・時刻訂正・選手交代が集計に反映される。
- 一度画面を開いた端末をオフラインにして記録し、通信回復後に同期できる。
- 別端末で別イベントを入力した場合は統合され、同じイベントの競合は上書きせず止まる。
- CSVとJSONバックアップを出力できる。
- スマホの「ホーム画面に追加」で利用できる。

最初は練習用の架空試合で確認してください。部員の写真・氏名を登録する前に、チーム内の閲覧範囲と利用ルールを決めてください。

## このクラウド開発環境にも接続する場合

環境設定に、同じ `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` を登録します。制限付きネットワークには、Project URLの実際のホスト（`xxxxx.supabase.co`）を追加します。値の変更後はアプリを再起動・再ビルドしてください。

ターミナルで次を実行すると、秘密情報を出力せずに確認できます。

```bash
npm run setup:check   # URLと公開キーの形式を確認
npm run setup:verify  # さらに認証サービスへのHTTP接続を確認
```

接続設定なしでこのコマンドを実行すると、未設定として終了します。ローカルの架空データモードは、その状態でも利用できます。

## うまくいかない場合

| 症状                        | 確認する場所                                                             |
| --------------------------- | ------------------------------------------------------------------------ |
| ビルドで公開キーのエラー    | Publishable / anonを使用しているか。片方だけ未設定でないか               |
| ログイン後にlocalhostへ戻る | SupabaseのSite URL / Redirect URLs                                       |
| デモ画面が出る              | Vercelの環境変数を登録し、Redeployしたか                                 |
| チーム作成・同期でエラー    | schema.sqlまたは必要なマイグレーションを適用したか                       |
| 同期が止まる                | 設定の状態表示、通信、権限、競合内容。端末データをJSONで退避してから対応 |
| メールが届かない            | Emailプロバイダ、迷惑メール、送信制限、SMTP設定                          |
| 既存チームが一覧にない      | 同じメールでログインしているか。管理者がメンバー追加したか               |

アカウント・接続先が未作成の段階では、実Supabaseのメール送信やVercelの公開URLは検証できません。コードの自動テストと本番サービスの接続確認は別々に行ってください。
